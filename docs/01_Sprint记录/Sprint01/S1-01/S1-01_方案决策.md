## 1. Outcome and capability

Module: driver-independent session projections. Interface: `@deepseek-ai/dsh-agent/session-projections` exports the existing inbox/turn-boundary definitions and schemas. The SessionProjectionRegistry seam serves the default loop and an independent driver. Adapters register only the requested keys. State versions, durable folds, wire encoding and invalid-splice errors remain identical.

## 2. File ownership

- `packages/core/agent/src/session-projections/index.ts`: the single public leaf export.
- `packages/core/agent/src/session-projections/internal/turn-boundary.ts` and `inbox.ts`: existing pure schema, init, fold and wire definitions.
- `packages/core/agent/package.json`: the leaf export to existing lib/types outputs; reuse the existing zod version and files layout.
- `packages/core/agent-loop/src/index.ts`: definition imports and compatibility exports only; the constructor registers the same keys.
- `packages/core/agent-loop/src/inbox.ts`: definition/schema imports and compatibility exports; the concrete Inbox stays with its driver.
- `packages/core/agent/tests/session-projections.spec.ts`, existing inbox/turn-boundary tests, public-export/NodeNext/pack/Loader checks and affected subsystem documentation.

## 3. Failure, recovery and execution scope

Import and registration create zero loops, factories, model calls, tools, processes or remote calls. Both drivers consume the same definitions; concrete Inbox commands remain with each driver.

## 4. Fixtures, regression and evidence

Use one Session, one turn and step, one message in each queue, and separate valid, out-of-range and duplicate-ID splice cases. Preserve stateVersion 1 for inbox and 2 for turnBoundary. Existing assertions move with the interface. Run the focused existing and new tests, built public exports, NodeNext, pack, actual Loader and affected documentation checks. Record command, environment, exit code, counters and immutable candidate identity. Product checks remain required.

## 5. Stages and responsibilities

One Issue owner implements and verifies this capability. HOST owns cross-Issue integration, merge, candidate assembly and common validation. Frozen fixtures can be developed independently. Production tests consume the real delivered producer. Design and implementation require their own authorization and real dependency evidence.
