## 1. Outcome and capability

Module: the existing AgentRegistry and SessionCommandController fork capability. Interface: `ForkAgentOptions { sourceSessionId; targetSessionId; atSeq? }`, optional `AgentFactory.forkAgent(ownerCtx, options)`, and registry capability/delegation methods. The existing unique factory slot owns delegation. Caller scope, fiber and ownerCtx match create/resume. The command validates live header or one persisted stat and direct workspace membership before claim; the ordinary branch retains its original history/seed/preset/ancestor path.

## 2. File ownership

- `packages/core/agent/src/index.ts`: optional factory fork method, input type and caller-bound registry delegation.
- `packages/api/session-controller/src/commands.ts`: native-first fork branch and private header-only preflight.
- `packages/api/session-controller/src/types.ts`, `src/client/sessions/manager.ts`, `service.ts`, `contract/sessions.ts`: stable intent and preserved error details.
- `packages/client/ui-chat/src/client/apply.ts`, `ui-workspace/navigation.ts` and `shortcuts.ts`: default fork error notification and locale.
- `packages/core/agent/tests/fork-driver.host.spec.ts`, existing command/session/service and core/session fork tests.
- Affected package READMEs, subsystem types, upgrade guides, generated catalogs and keyless UI snapshots.

## 3. Failure, recovery and execution scope

The native branch reads zero local history bodies, snapshots or seeds and starts zero ordinary agents or model calls. Driver errors and unknown results preserve code, message and details. A workspace-attach failure exposes the confirmed child ID; success returns the actually published handle. Stable request intent survives repeated clicks. Invalid or unfinished boundaries are rejected by the native provider. Factory disposal and HMR release the declared capability with a real terminal result.

## 4. Fixtures, regression and evidence

Use one source header, one target, one completed boundary, one native fixture factory and one ordinary factory. Change one precondition per failure case. Existing assertions move with the interface. Run the focused existing and new tests, built public exports, NodeNext, pack, actual Loader and affected documentation checks. Record command, environment, exit code, counters and immutable candidate identity. Product checks remain required.

## 5. Stages and responsibilities

One Issue owner implements and verifies this capability. HOST owns cross-Issue integration, merge, candidate assembly and common validation. Frozen fixtures can be developed independently. Production tests consume the real delivered producer. Design and implementation require their own authorization and real dependency evidence.
