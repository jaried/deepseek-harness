## 1. 用户结果与能力

Module：既有AgentRegistry与SessionCommandController的fork能力。Interface：`ForkAgentOptions { sourceSessionId; targetSessionId; atSeq? }`、可选`AgentFactory.forkAgent(ownerCtx, options)`及registry能力查询/委托方法。既有唯一factory slot拥有委托；caller scope、fiber与ownerCtx与create/resume对称。command在claim前验证live header或一次persisted stat及直接workspace关联；ordinary分支保留原history/seed/preset/ancestor路径。

## 2. 文件责任

- `packages/core/agent/src/index.ts`：可选factory fork方法、输入类型与caller-bound registry委托。
- `packages/api/session-controller/src/commands.ts`：native-first fork分支与私有header-only前检。
- `packages/api/session-controller/src/types.ts`、`src/client/sessions/manager.ts`、`service.ts`、`contract/sessions.ts`：稳定意图与错误details保真。
- `packages/client/ui-chat/src/client/apply.ts`、`ui-workspace/navigation.ts`与`shortcuts.ts`：默认fork错误通知与locale。
- `packages/core/agent/tests/fork-driver.host.spec.ts`、既有command/session/service与core/session fork测试。
- 受影响package README、子系统类型、升级指南、生成catalog与keyless UI快照。

## 3. 失败、恢复与执行范围

native分支读取本地正文、snapshot与seed均为零，普通Agent创建和模型调用均为零。driver错误和unknown保留code、message与details。workspace attach失败展示已确认child ID；成功只返回实际发布handle。稳定请求意图沿再次点击保持。非法或未完成边界由native provider拒绝。factory dispose（资源释放）与HMR（热模块替换）释放声明能力并产生真实终态。

## 4. 最小数据、防回归与证据

使用一个source header、一个target、一个已完成边界、一份native fixture（测试前置数据）factory和一份ordinary factory。失败场景每次只改变一个前置。既有assertion随Interface迁移。执行旧/新聚焦测试、构建公开导出、NodeNext、pack、真实Loader和受影响文档检查。保存命令、环境、exit code、执行计数与不可变候选身份。产品检查保持required。

## 5. 阶段与责任

单票owner实现并验证本能力。HOST负责跨票集成、合并、候选装配与共同验证。冻结fixture可独立研发，生产测试消费真实交付的producer。设计与实施分别取得授权，并消费真实依赖证据。
